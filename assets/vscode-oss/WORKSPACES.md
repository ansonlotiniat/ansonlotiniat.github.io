# Code - OSS public workspaces

Last updated: 2026-08-09 15:15 CST

## Scope

The embedded Code - OSS Explorer mounts a disposable multi-root `tmp:` workspace generated by `scripts/build-vscode-workspace.mjs`. It contains only:

- source from Anson's public repositories, pinned to explicit Git commits;
- selected source from the current AnsonOS project;
- generated navigation and provenance Markdown.

Private repositories, credentials, Git configuration, local home-directory files, unpublished datasets, build secrets, and editor/account storage are excluded. Browser edits are temporary and reset on reload.

## Workspace roots

- `00-START-HERE`: scope and navigation.
- `01-ALGORITHMS`: real implementations of shortest path, min-cost max-flow, food-rescue matching, flood-aware shelter routing, Pareto-based grant allocation, and accessibility linting.
- `02-OPEN-SOURCE`: complete text source/runtime trees from `agent-trust`, `latexmark`, and `gm2-conflict-aware-hvp`; generated binary figures and unrelated release collateral are omitted.
- `03-ANSON-OS`: current local App manifest, consistency validator, and Code - OSS bootstrap.

## Runtime integration

The stock web workbench registers an in-memory provider for the `tmp:` scheme but exposes no embedder API for populating it before workspace initialization, and its search service has no provider for that scheme. The local Code - OSS bundle therefore contains two narrow, documented hooks: one invokes `globalThis.__ANSON_SEED_VSCODE` immediately after the built-in provider is registered, and one registers `globalThis.__ANSON_SEARCH_PROVIDER` for file and text search during search-service construction. `bootstrap.js` supplies the files and `.code-workspace` definition; `workspace-search.js` searches only the same public in-memory payload. No Explorer, editor, Quick Open, Search view, or file-tree UI is reimplemented.

The compatibility query `assets/vscode-oss/index.html?runtime=file` selects the same classic bundle over HTTP for automated diagnostics. Production selects it only when `location.protocol === "file:"`. A real Chrome regression test in `tests/vscode-file-runtime.spec.mjs` opens the portfolio through `file://`, waits for the genuine workbench, verifies all four roots, searches for `risk.js`, and opens it in Monaco.
