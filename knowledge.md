## Reframed goal

Build a bilingual personal homepage that behaves like Anson Lo’s working Mac rather than a document or portfolio feed. The current metaphor is “AnsonOS”: a deliberately faithful macOS Tahoe 26 desktop shell where a visitor searches for Anson, opens the tools he works through, and learns how he thinks from the interface of each tool.

Temporary public-state override (2026-08-01): retain the interactive desktop and application chrome, but suppress all substantive personal biography, roles, projects, writing, and work descriptions. Every such public-facing string is currently replaced by `建設中建設中建設中建設中`. Generic operating-system/application controls, field labels, product names, and the non-endorsement notice remain intact. Contact destinations remain functional but are shown only as generic `Email` and `GitHub` labels. The Goodnotes workspace added at the user's request on 2026-08-02 is a deliberate exception: it contains newly authored, generic educational examples rather than private or biographical source material. The Books workspace is a second deliberate, narrowly scoped exception requested the same day: it records the three books shown in Apple Books’ Continue shelf, their authors, visible reading percentages, and cover-only library imagery. The Visual Studio Code workspace is a third explicit exception requested on 2026-08-03 and expanded by the user on 2026-08-09: its initial state records the currently visible Welcome interface, five visible Recent names/paths, walkthrough cards, installed-tool labels, editor actions, and status labels, then exposes a real browser Code - OSS workbench with a 123-file public code workspace. Remote source is taken only from seven public repositories at pinned commits; private repositories, credentials, extension storage, account state, terminal output, local home files, and hidden Recent entries remain excluded.

The site must not assume that a portfolio is something to scroll from top to bottom. Its primary navigation is application- and state-based: Explore reveals workspaces, the Dock launches them, and several movable windows can remain open together. Xcode represents engineering systems, Visual Studio Code represents iGEM software/modelling/wiki delivery, Overleaf represents writing and editing, Goodnotes represents mathematics/physics/chemistry study notes, Books represents Anson’s current reading and library, and Finder represents identity, method, and contact.

## Current design decisions

- The homepage is a fixed “AnsonOS” desktop rather than a vertically scrolling page. Its shell uses the measured geometry and interaction hierarchy of [macOS Web](https://macosweb.netlify.app/) as the canonical browser reference while retaining macOS Tahoe 26 application resources and Anson’s own MIT/workspace content. This is a clean-room visual reimplementation, not a wholesale copy of the reference source.
- The menu bar is a fully transparent 31 px interaction layer, following the user’s Tahoe direction rather than adding the reference site’s dark overlay. The wallpaper remains visible edge-to-edge and a compact two-layer text shadow keeps controls readable. Its right-side menu extras use four equal 28 px slots for input source, search, Wi-Fi, and Control Center, separated by a consistent 6 px desktop gap; their centres are exactly 34 px apart on the same 15.5 px vertical axis. Battery and clock retain content-driven widths with matched 5 px inner padding. Responsive layouts use a consistent 5 px gap and remove the entire hidden Control Center wrapper, preventing a doubled empty gap. Apple, File, Edit, View, Go, Window, and Help are working menus with keyboard navigation; Control Center, battery, and clock open native-style panels. Clicking the desktop activates Finder, and right-clicking it opens a bounded macOS context menu with working Clean Up and View Options controls.
- The Dock is a compact content-width bar positioned 4 px above the bottom edge. It matches the reference’s 66 px height, 14 px corner radius, neutral low-opacity glass, 20 px backdrop blur, and heavy grounded shadow. Default entries are 58 px and fine-pointer magnification is a continuous cursor-distance curve rather than discrete CSS hover steps: icons reach 128 px at the pointer, nearby icons fall away with a Gaussian curve, their transformed centres repack without overlap, and the glass stretches with the same animated total width. The implementation animates compositor transforms instead of width/height layout. A single shared name pill is positioned from the active icon's live transformed rectangle, staying centred 12 px above it throughout magnification and repacking. When the pointer crosses a gap, the previous App name remains visible until the pointer actually intersects the next icon; switching text never hides the pill. Keyboard focus uses the same pill. The icon order is Finder, the real macOS 26 Apps launcher, Xcode, Visual Studio Code, Overleaf, Goodnotes, Books, and Mail. All are pinned-App entries, so there are no invented separators between Finder, work, and Mail; open-state dots remain. Overleaf is the only synthetic Dock plate: its size and corner curve are derived directly from Xcode's opaque plate (`204/256` canvas occupancy and `44/204` radius), not from a guessed universal pixel target. The native Goodnotes and Xcode assets independently measure the same 206×206 strong-alpha boundary inside their 256×256 canvases.
- The former aurora illustration, giant `ANSON LO.OS` hero, live workspace widget, wallpaper parallax, and Lake Louise desktop were removed from the active shell. The current wallpaper is a real 2560×1600 view of MIT’s Great Dome and Killian Court; Anson’s identity belongs inside Finder rather than being printed over the photograph.
- Finder, Apps, Folder, Mail, Xcode, Goodnotes, and Books use icons converted directly from installed application resources on this build Mac. The Apps image comes from `/System/Applications/Apps.app`, making the Explore launcher the same search-and-colour-grid tile shown by Tahoe rather than a custom magnifying-glass invention. Visual Studio Code uses its installed current macOS resource. Overleaf remains a documented Simple Icons mark inside a custom multi-layer glass tile; its Dock plate follows the measured Xcode surface size and radius so its silhouette matches a native neighbour.
- Fine-pointer devices use an intentionally oversized 65×100 px cursor reconstructed from the user-supplied reference. The cursor is a 13×20 SVG pixel grid with a pure-white solid interior, pure-black outline, and transparent exterior. It preserves the reference’s long left edge, one-cell diagonal staircase, horizontal arm, and hooked lower outline; it has no glow, hover enlargement, or simulated depth. Pressing shifts it by two pixels. Touch/coarse-pointer devices keep their native pointer behaviour.
- Launchpad and Spotlight are now separate macOS interactions:
  - the authentic Apps entry immediately after Finder opens a full-screen, 25 px-blurred Launchpad with a searchable four-column grid and the Dock still available;
  - the menu-bar search control, `/`, `⌘K`, or `⌘Space` opens the compact Spotlight-like Explore interface when the browser receives that event;
  - filter by English or Traditional Chinese keywords;
  - use Tahoe-style All Apps, Engineering, iGEM, and Writing browse chips;
  - use arrow keys and Enter to select;
  - use `⌥0`–`⌥4` as direct application shortcuts.
- Real macOS normally reserves `⌘Space` for system Spotlight before a webpage can see the keystroke. The site still listens for it, but the visible Explore controls, `/`, and `⌘K` are necessary in-page fallbacks.
- Windows are real interface state, not decorative screenshots. Their default presentation is compact and centred like the reference rather than nearly full-screen: Finder is capped at 840×570, Visual Studio Code now uses its explicitly measured 1152×768 native geometry, the larger Xcode/Overleaf workspaces remain 980×650, and Books uses the measured 1024×768, with native corner/titlebar treatment and grounded shadows. They can be opened together, focused by z-order, dragged by their title bars, minimized into and restored from the Dock, maximized, closed, and addressed through `#about`, `#xcode`, `#vscode`, `#overleaf`, `#goodnotes`, and `#books`.
- Finder/About presents identity, a three-part working method, current iGEM and Speech Society work, direct email/GitHub contact, and the interface/trademark note.
- Xcode/Engineering has two switchable project files:
  - `SportsDaySystem.swift` explains two years of lead interface design/development through one entry point whose information priority changes before, during, and on site;
  - `DebateOperations.swift` shows the team mini program and internal tournament system as different role views over shared information.
- Visual Studio Code is no longer a hand-built metaphorical iGEM editor. `assets/vscode-oss/` contains the official Code - OSS 1.131.0 web build (tag commit `3a03d6f72d628a7741c29f456b4ddbb5ae68502c`), its MIT licence/third-party notices, and Traditional Chinese localization. A clean-room initial overlay reproduces the exact authorized Welcome state while the official workbench boots behind it; its first Start action opens a genuine four-root multi-folder workspace (`START HERE`, `ALGORITHMS`, `OPEN SOURCE`, and `ANSON OS`) in the real Explorer and Monaco editor. The workspace has 123 text files: complete source/test trees from four public MIT algorithm repositories, complete text source/runtime trees from three larger public projects, retained licences and pinned provenance, plus selected current-site source. It is mounted through Code - OSS's built-in in-memory `tmp:` provider, remains editable for the session, and resets on reload. A matching lightweight provider restores native `⌘P` file search and Search-view text results for `tmp:`; the Quick Open and Search interfaces themselves remain Code - OSS. The pinned core differs from upstream only at the documented provider-seed and search-registration hooks. The iframe is an eager, explicit `assets/vscode-oss/index.html` resource: this avoids the directory-listing failure that occurs when the portfolio is opened directly with `file://`, while HTTP/GitHub Pages preload the core as a native module. Chrome blocks cross-file module imports for opaque local-file origins, so direct local-file use selects a generated classic-IIFE compatibility runtime instead; it provides the same real workspace without a server, while the web-extension worker remains an HTTP-only capability. The complete 20,600-entry Traditional Chinese fallback array makes the separate 1.01 MB English base array redundant, so only the 0.97 MB localized array is loaded. The small captured-state host and Codicons render independently of the non-blocking 1.31 MB workbench stylesheet, while the 17.65 MB workbench module continues loading behind the visible capture. A repeated parent/iframe handshake, same-origin state fallback, early message listener, structured runtime-error signal, six-second abnormal-load watchdog, retry control, and versioned URLs prevent a missed ready event or stale cache from leaving the startup cover in place. Early commands are queued until the real workbench is ready. Provenance and build details are in `assets/vscode-oss/SOURCES.md` and `assets/vscode-oss/WORKSPACES.md`.
- Overleaf/Writing changes the source and compiled preview together:
  - `macao-diary.tex` uses the real `《澳門日記—回歸故事集》` editorial-credit image and a pointer magnifier;
  - `between-bells.tex` typesets Anson’s supplied poem excerpt;
  - Recompile provides a small live compilation interaction.
- Goodnotes/Study uses the measured 900 px library width and 1024×768 editor geometry without scaling its typography down with the browser window. At a 1440×900 desktop the library is 900×781: the unavailable vertical portion scrolls inside the App instead of shrinking the whole 900×1068 native design to 674 px wide. Library text now follows fixed macOS point sizes—13 px navigation/card names, 9.5–10 px secondary metadata, 12.5 px toolbar/menu copy, and a 28 px large title—rather than container-width units that previously produced 4.48–8.21 px labels. The library keeps its native sidebar, mixed folder/document flow, large-title and sticky-header states, full search, filter/view menus, and grouped New palette. Its hover contract now follows the live 7.1.6 App rather than generic web-card conventions: folder/document media never lift, resize, brighten, or gain a hover plate; the centred title stays geometrically fixed, turns implementation blue `#2e88d4`, and gains an absolutely positioned 5 px grey chevron in one frame. Sidebar rows use an immediate `rgba(0,0,0,.04)` pill, top controls and the Filter/New surfaces retain their resting appearance, and document context-menu rows switch immediately to `#f5f5f5`. Right-clicking a document gives it the live pale-blue selected plate and opens the measured five-action context menu; that plate is now painted with an outward box-shadow instead of adding 5.99 px padding and translating the card, so its bounding box remains fixed. Grid/list switching now makes list rows span the available width instead of collapsing every document to about 82 px. Search isolates keyboard focus, filtering updates the title and empty state, favorites and duplication update the collection, and non-destructive demo-only actions give explicit feedback instead of acting as dead buttons. Opening a note switches to the native editor geometry with the full read/edit toolbar, centred page, and page sidebar; new notes correctly begin at one page, existing notes retain their page count, and Add Page updates the thumbnail list, active page, footer, and status. The seven documents now contain 35 separately authored study pages rather than one recycled template: every page has its own title, subject-specific bullet notes, formula, SVG notebook sketch, highlight rhythm, and reminder.
